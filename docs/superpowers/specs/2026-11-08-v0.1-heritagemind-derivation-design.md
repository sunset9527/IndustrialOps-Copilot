# IndustrialOps Copilot v0.1 派生与去领域化设计

日期：2026-11-08

状态：已由用户确认方案 A，待规格复核

目标仓库：`E:\python\LLM\IndustrialOps_Copilot`

代码母体：`E:\python\LLM\IntangibleCulturalHeritage_MultiAgent`

迁移基线：HeritageMind `1edc5c4`（`main` 与 `origin/main` 同步）

## 1. 目标

在保留 IndustrialOps 阶段 0 Git 历史和两个冻结知识包的前提下，从 HeritageMind 的已提交基线选择性迁移通用工程能力，建立可独立安装、启动和测试的 IndustrialOps Copilot v0.1 底座。

本阶段只完成项目派生和去领域化，不实现设备知识包加载、工业检索规则、诊断工作流、设备台账、工单、人工审批或工业前端业务页面。这些能力分别属于 v0.2 至 v0.5。

## 2. 已确认方案

采用“选择性迁移到现有 IndustrialOps 仓库”，不复制 HeritageMind 的 `.git`，不覆盖 IndustrialOps 已有历史，不修改 HeritageMind 工作区。

选择该方案的原因：

1. IndustrialOps 已有独立的阶段 0 提交历史和冻结产物，整仓覆盖会破坏可追溯性。
2. HeritageMind 的非遗领域和图谱耦合较多，选择性迁移更容易证明运行时不存在图谱依赖。
3. 迁移清单可以精确记录源提交、保留文件、删除文件和适配内容。

不采用以下方案：

- 整仓复制后删除：容易残留非遗数据、图谱模块、旧配置和旧指标。
- 从零重建：无法体现 HeritageMind 作为代码母体，也会重复建设已经验证的通用能力。

## 3. 版本与历史策略

IndustrialOps 保留现有 Git 仓库和阶段 0 提交。v0.1 新增迁移记录，至少包含：

- 源仓库名称与地址；
- 源提交 `1edc5c4`；
- 迁入文件或模块；
- 未迁入模块及理由；
- 迁移后的重命名和领域解耦；
- 后续从 HeritageMind 同步通用修复的方式。

现有未跟踪的 `scripts/` 是阶段 0 资料下载工具，不删除、不覆盖。其纳入版本控制与否由本阶段的仓库边界测试和版权/敏感信息检查决定，不能在未审核时批量提交。

## 4. 命名与运行边界

统一采用以下标识：

| 项目项 | v0.1 值 |
|---|---|
| Python 发布名 | `industrialops-copilot` |
| Python 导入包 | `industrialops` |
| 产品显示名 | `IndustrialOps Copilot` |
| 本地数据库名 | `industrialops` |
| Redis/队列前缀 | `industrialops:*` |
| 本地 API 端口 | `8100` |

## 5. 迁移范围

### 5.1 保留并去领域化

从 HeritageMind 选择性迁移以下能力：

- FastAPI 应用装配、生命周期、健康检查和错误协议；
- SQLAlchemy、Alembic、用户、认证、权限和管理账户初始化；
- 审计基础及其通用事件结构；
- 请求上下文、请求大小、安全响应头、限流、并发和日志脱敏；
- 文档上传、安全校验、解析、任务队列和 worker 基础；
- BM25、BGE-M3 向量检索、RRF 融合、CrossEncoder 重排和索引快照；
- 查询改写、通用检索指标和评测执行骨架；
- LangGraph 状态、事件、编排和错误降级骨架；
- Vue 3 工程、认证状态、API 客户端、通用错误处理和基础布局；
- Docker、Compose、环境样例和启动校验。

迁入模块必须放入 `industrialops` 包命名空间。源代码中的 `craft`、`heritage`、非遗数据路径和品牌文案不能作为运行时默认值保留。

### 5.2 明确不迁移

以下内容不得进入 v0.1 运行时：

- `src/graph/` 全部实现；
- `graph_agent`、图谱构建、抽取、审核、投影、调度和可视化；
- `networkx`、`pyvis` 等仅为图谱服务的依赖；
- craft/history/heritage 三专家及其提示词；
- 多智能体辩论默认链路；
- 非遗百科、传承人、文化叙事、音频导览和媒体展示；
- 非遗数据集、评测题、指标和种子内容；
- `craft_id`、`craft_name` 作为通用检索接口的必需参数；
- HeritageMind 的数据库、Redis 键、容器名、端口和产品品牌默认值。

### 5.3 延后实现

以下目录可以建立空边界或接口占位，但不得在 v0.1 实现业务逻辑：

- `knowledge`：设备知识包加载属于 v0.2；
- `workflow`：工业诊断状态与节点属于 v0.3；
- `domain`、`work_orders`：设备和工单领域属于 v0.4；
- 工业诊断工作台和工单页面属于 v0.5。

## 7. 应用与数据流

v0.1 的最小可运行数据流为：

```text
Vue 基础页面
  → IndustrialOps API 客户端
  → FastAPI 应用
  → 认证 / 健康检查 / 上传基础接口
  → 通用服务与数据库
```

通用检索能力通过单元和集成测试验证，但不接入冻结知识包，也不暴露伪装成工业诊断的生产接口。LangGraph 仅提供可导入、可构建的中性骨架；不得返回诊断、维修步骤或工单草稿。

## 8. 错误处理与安全

- 启动配置缺失时返回明确错误，不静默回退到 HeritageMind 路径或数据库。
- 本地模型缺失时允许健康状态报告未就绪，但不在运行时自动下载模型。
- 上传沿用文件类型、大小和路径安全校验。
- 对外错误使用统一协议，内部异常经过脱敏后记录。
- 删除图谱后，任何残留导入都必须在测试或启动阶段失败，不能延迟到业务请求时才暴露。
- v0.1 不连接真实设备，不执行工业写操作，不产生维修建议。

## 9. 测试策略

实现遵循测试驱动开发。每个迁移切片先写失败测试并确认失败原因，再迁移最小代码使其通过。

### 9.1 仓库与独立性

- 能从 IndustrialOps 根目录安装和导入 `industrialops`；
- 运行时文件中不存在指向 HeritageMind 目录的路径；
- 迁移记录中的源提交固定为 `1edc5c4`；
- 阶段 0 的 68 项测试继续通过。

### 9.2 去领域化

- Python 运行时模块不存在 `industrialops.graph`；
- 生产依赖不包含只服务于图谱的 `networkx` 和 `pyvis`；
- 应用路由、默认配置和前端构建产物不出现非遗品牌、craft 专属参数或图谱入口；
- 不迁移非遗评测数据和公开指标。

### 9.3 通用能力回归

- 认证、密码策略、错误脱敏和请求安全的适用核心测试通过；
- 上传安全、PDF/文档解析和任务状态的适用核心测试通过；
- BM25、向量接口、RRF、重排和检索指标的通用测试通过；
- LangGraph 中性骨架可构建且失败时走安全降级；
- FastAPI 健康检查和就绪检查可调用；
- Vue 单元测试与生产构建通过；
- Docker/Compose 配置解析成功，容器名、端口和数据库均为 IndustrialOps 值。

HeritageMind 原测试不整包复制。只迁移能够证明通用模块行为、且不依赖非遗数据的测试；领域测试在迁移清单中记录为“不适用”。
