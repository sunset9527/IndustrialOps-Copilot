# 阶段 0：结构化候选保守审核设计

**日期：** 2026-11-08  
**状态：** 待用户审阅  
**范围：** 审核 `data/structured/candidates/` 中的 1,949 条候选，生成可审计决定；不直接开发诊断或维修执行功能。

## 1. 审核状态与结果

每条候选产生一条决定，状态只能为：

- `include`：可进入后续正式结构化知识的候选；
- `not_retrievable`：保留审核证据，但不得进入索引或回答；
- `exclude`：明确范围外、无实质运维内容或类别不成立。

候选原文件不被覆盖。决定输出到独立 JSONL 台账，保留候选 ID、类别、设备包、决定、理由、来源、页码、证据定位和审核日期。

## 2. 保守纳入规则

候选仅在同时满足以下条件时自动纳入：

1. 来源和双语证据字段完整，候选仍为 `review_required`；
2. 设备包仅为 `cnc_pack_v1.0.0` 或 `dry_vacuum_pump_pack_v1.0.0`；
3. 候选标签由正文的明确代码、部件名、症状/故障词或维护/安全动作词触发；
4. 证据正文未出现范围外型号、选件或设备标记；
5. 正文不是目录、导航、订货目录、纯交叉引用或仅举例说明。

安全和维护类候选只保留原页中已有的证据文本；审核器不生成新的操作步骤、顺序、参数或故障因果关系。

## 3. 阻断和排除规则

以下情况自动标为 `not_retrievable`：

- 出现 SMTC、TSC、机器人、托盘库、第四/第五轴、C/R 变体、远程/串口附件或其他机型标记；
- 同一候选同时出现多个可相互冲突的设备型号或选件，且不能在同一证据中分离；
- 安全/维护证据包含危险动作，但没有隔离能源、泄压、起吊/防护等必要条件的明确上下文；
- 仅有泛化警告、标题或关键词，无法支持候选标签。

以下情况标为 `exclude`：

- 纯目录、导航、文档/订货索引、版权或非运维说明；
- 明确只适用于范围外设备或选件；
- 候选类别与证据正文不一致。

## 4. 数据流与验证

候选 JSONL按类别读入，稳定排序后逐条决定；输出 `data/structured/review/structured_candidate_decision_ledger_v1.jsonl` 和清单。输入不变时决定 ID、顺序和清单哈希必须稳定。

测试先行验证：

1. 明确的、同设备包的安全候选可纳入，且证据完整；
2. 含范围外选件/型号词的候选必须不可检索；
3. 目录/导航候选必须排除；
4. 无来源字段或未知设备包的候选必须拒绝；
5. 决定台账覆盖全部输入候选，且不重复；
6. 只有 `include` 才能进入后续正式结构化候选集。

## 5. 非目标

- 不宣称自动审核等同于制造商认证或现场安全许可；
- 不删除原始英文、中文或候选证据；
- 不让 `not_retrievable`/`exclude` 候选进入检索、问答或冻结包。
