# 阶段 0：双设备知识包解析、双语派生与冻结设计

**日期：** 2026-11-07  
**状态：** 已获用户确认，待实现  
**范围：** Haas VF-2（NGC，标准配置）和 Edwards nXDS6i/10i/15i/20i（标准型号）的阶段 0 知识包建设。

## 1. 决策与边界

### 1.1 已确认决策

- 原始 PDF 保留为只读证据，不改写、不翻译覆盖、不提交公开仓库。
- 解析范围覆盖已归档的 40 份 PDF；正式入库范围由设备、型号、控制器、选件和故障域白名单决定。
- Haas 已有的官方简体中文资料，直接作为中文原文入库。
- Edwards 及 Haas 当前中文版缺失的范围，保留完整英文原文，只对**通过白名单的入库片段**生成中文项目译文。
- 项目译文必须标记为 `project_translation`；英文原文、文档版本、来源文件和页码始终是事实权威与引用依据。
- 不新增外部资料；所有结构化数据、译文和评测均只能从本次已归档来源派生。

### 1.2 设备白名单

| 知识包 | 允许范围 |
|---|---|
| `cnc_pack_v1.0.0` | Haas VF-2 标准配置：NGC、40 锥度、三轴、8100 rpm、20 刀位伞式刀库、标准润滑和标准冷却 |
| `dry_vacuum_pump_pack_v1.0.0` | Edwards nXDS6i/10i/15i/20i 标准型号 |

排除 Haas SMTC、TSC、第四/第五轴、机器人、托盘库、其他机型，以及 Edwards C/R 变体和远程/串口等附件。超出范围的问题在后续产品层必须返回范围不足，不可通过模型猜测补足。

## 2. 方案选择

选择“完整页级解析 + 白名单过滤 + 范围内中英双语入库”的混合方案。

- 完整解析保证后续每一条知识都可回溯，且不会因为早期人工漏页而丢失证据。
- 白名单是正式索引唯一入口，避免混合页面中的排除型号、选件或旧控制器污染检索。
- 中文译文只为已入库英文片段生成；不会把整本无关英文手册翻译后误纳入知识库。
- 告警、部件、症状、维修和安全规则由可追溯片段生成，并在冻结前审核。

## 3. 数据流与目录

```text
data/raw_archive/                     # 已下载原始资料；只读证据
  -> source_manifests/                # 文件来源、版本、页数、SHA-256
  -> derived_corpus/pages/            # 一页一条的解析原文记录
  -> derived_corpus/candidates/       # 带分类/适用范围的候选片段
  -> derived_corpus/indexable/        # 经白名单批准的入库片段
  -> derived_corpus/translations/     # 英文入库片段的中文项目译文
  -> structured/                      # alarms/components/symptoms/... JSONL
  -> evaluation/                      # 与语料分离的评测集和验收结果
  -> packs/                           # 只读冻结包、清单和内容哈希
```

每个页级/片段级记录最少包含：

```json
{
  "pack_id": "dry_vacuum_pump_pack_v1.0.0",
  "source_id": "A73501880_L",
  "source_file": "edwards_nxds_instruction_manual_A73501880_L_en.pdf",
  "source_sha256": "…",
  "page_number": 1,
  "section": "…",
  "text_en": "…",
  "text_zh": "…",
  "translation_status": "project_translation",
  "applicability": "approved",
  "applicable_models": ["nXDS6i", "nXDS10i"],
  "evidence_locator": "A73501880_L:p.1"
}
```

中文官方原文使用 `translation_status: official_zh`；不应翻译、无中文文本的技术标识（报警码、零件号、型号、单位、端子/按钮名称）保持原样。

## 4. 组件职责

1. **来源审计器**：读取最终来源清单，确认每份文件存在、哈希匹配、页数可读，并把来源元数据写入统一清单。
2. **页级解析器**：从 PDF 逐页提取文本；记录提取失败、扫描/OCR 需求和正文缺失页，不静默丢弃。
3. **候选分段器**：按标题、段落、表格邻近文本与页码建立候选片段；不跨来源拼接。
4. **适用性过滤器**：依据显式规则把片段标为 `approved`、`excluded` 或 `review_required`。只有 `approved` 能进入正式语料。
5. **双语派生器**：仅对 `approved` 且英文为主的片段写入中文项目译文；保留英文原文并标注译文状态。
6. **结构化提取审核器**：从可追溯片段创建告警、部件、症状、故障模式、维护任务和安全规则候选；没有来源定位的记录拒绝写入正式文件。
7. **冻结器**：校验覆盖矩阵、来源完整性、跨设备隔离和评测集分离后，生成知识包清单与确定性内容哈希。

## 5. 安全与错误处理

- 原始文件哈希变化、缺少文件、PDF 不可读或页数不一致：终止冻结并报告来源错误。
- 不能确定设备/型号/控制器适用性：标记 `review_required`，不得进入索引。
- 英文译文缺失：原文可以留在候选区，但不得作为“中文已完成”进入冻结包。
- 告警和维修建议必须带 `source_id`、页码、适用型号及证据定位；否则拒绝进入结构化文件。
- 任何危险操作、LOTO 未确认、未知介质、未泄压或超出设备范围的事项，必须被后续安全规则覆盖为拦截或升级，不能生成可执行维修指令。

### 5.1 解析进度可见性

页级解析器必须提供终端实时进度和一个本地状态 JSON 文件，但不建设网页界面。每完成一份来源 PDF 都刷新一次状态，至少包含：总/已完成来源数、总/已处理页数、当前来源 ID 与文件、已提取页数、空文本页数、失败来源数、状态（`running`、`completed` 或 `failed`）和错误摘要。

终端只输出聚合的“每来源”进度，避免 1332 页逐页刷屏；状态 JSON 供用户随时打开查看，也为后续网页入库页复用。原始资料和最终页级语料的可追溯字段不因进度展示而改变。

## 6. 测试与验收

实现采用测试先行。首批行为测试应验证：

1. 变更后的原始文件哈希会阻断冻结；
2. 每个页级记录都有来源文件、页码和来源哈希；
3. Edwards 英文批准片段必须同时保留 `text_en` 与标记为项目译文的 `text_zh`；
4. Haas 官方中文批准片段使用 `official_zh`，而非项目译文；
5. `review_required`、排除型号和跨设备记录无法进入 `indexable`；
6. 结构化报警/安全规则无证据定位时被拒绝；
7. 冻结包内容哈希在输入不变时可重复。

阶段 0 冻结还必须满足《阶段0-资料覆盖矩阵》的九项条件，尤其是：所有必需来源存在、混合页面完成白名单、Haas/Edwards 告警范围按声明完整、评测集与知识库分离、并保存只读归档副本。

## 7. 非目标

- 本设计不实现诊断 Agent、前后端、数据库 API 或工作流界面。
- 不把厂商手册上传至 GitHub，不把项目译文表述为厂商官方译本。
- 不增加新设备、新资料或未声明的故障域。
