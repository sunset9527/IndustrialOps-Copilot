# v0.5：工业前端与演示闭环设计

**日期：** 2026-11-12  
**状态：** `release_verified`（2026-11-18）
**范围：** 在不修改阶段 0 冻结知识包内容、不改变 v0.3 诊断语义和 v0.4 工单审批规则的前提下，将现有 Vue 占位首页改造成可真实调用后端的工业运维演示前端，完成 CNC 主案例与干式真空泵迁移案例的浏览器闭环。

## 1. 目标

v0.5 交付一个“演示主链路优先”的工业工作台。用户应能在同一应用中：

1. 登录并识别当前角色；
2. 查看并选择合成演示设备；
3. 使用服务端返回的知识包、型号和控制器上下文发起诊断；
4. 清楚阅读候选原因、检查顺序、安全前置条件、不确定性和可追溯引用；
5. 基于允许的诊断结果创建证据绑定工单草稿；
6. 由 `approver` 或 `admin` 在界面中批准或拒绝工单；
7. 不修改代码、不重启前后端即可在 CNC 与真空泵之间切换。

本阶段首先达到 `automated_verified`。只有真实浏览器中的 CNC 与真空泵演示链路均通过后，才能标记 `release_verified`。

## 2. 已确认边界

### 2.1 本阶段包含

- Vue 登录、路由守卫和角色感知界面；
- 只读设备总览；
- 集中式诊断工作台；
- 证据、安全和不确定性检查器；
- 工单草稿抽屉；
- 工单列表、详情、批准和拒绝；
- 统一加载、空数据和错误状态；
- CNC 主演示与真空泵迁移演示；
- 为前端通用设备切换所必需的最小后端响应扩展；
- 前端组件测试、全量回归和生产构建。

### 2.2 本阶段不包含

- 设备新增、编辑、删除或完整资产管理后台；
- 工单指派、开始、完成、关闭等完整生命周期操作界面；
- 知识包上传、索引构建或评测管理界面；
- 真实设备控制、传感器流、实时曲线或预测性维护；
- 外部 CMMS、EAM、MES、SAP 或 Maximo 集成；
- 新增设备、新增知识资料或修改冻结评测集；
- 图谱、图数据库、Graph Agent 或关系图可视化；
- Docker 与生产反向代理交付，这些仍属于 v0.6。

## 3. 视觉与交互方向

视觉方向固定为“精密机械风，但保持简洁”。

### 3.1 设计语言

- 石墨色用于应用骨架和主导航；
- 冷灰金属色用于页面背景、分隔与设备铭牌；
- 低饱和钢蓝用于主要操作和选中状态；
- 安全橙只用于安全风险、待审批数量和需要注意的状态；
- 红色只用于拒绝、失败或破坏性动作；
- 设备编号、请求 ID、知识包版本等使用等宽数字风格；
- 组件偏方正，采用细边框、轻阴影和 4/8px 间距体系；
- 不使用大面积渐变、玻璃拟态、装饰性图表或不存在的实时指标。

安全状态必须同时使用图标、标题和文字，不得只依赖颜色。正常正文与背景对比度至少满足 WCAG AA。所有主要交互目标高度不低于 44px，并保留清晰键盘焦点态。

### 3.2 桌面布局

```text
顶栏：产品标识 / 知识包与 API 状态 / 当前用户
├── 左侧主导航：设备总览 / 诊断工作台 / 工单审批
└── 主工作区
    ├── 设备铭牌：资产、型号、控制器、知识包、状态
    ├── 中央：问题输入与结构化诊断结果
    └── 右侧：证据 / 安全 / 信息缺口检查器
```

设备切换放在主工作区的设备铭牌中，不把设备列表塞入狭窄侧栏。工单草稿使用抽屉或结果区内的渐进展开，审批队列使用独立路由。

### 3.3 响应式布局

桌面端保留三层信息结构。窄屏改为单列：设备铭牌、问题输入、诊断结果、证据与安全依次排列；主导航折叠为顶部菜单。不得产生横向滚动，不得用隐藏安全信息的方式适配小屏。

## 4. 信息架构与组件边界

前端使用 Vue Router，提供以下路由：

| 路由 | 作用 | 权限 |
|---|---|---|
| `/login` | 用户名、密码登录及错误反馈 | 公开 |
| `/assets` | 只读设备总览和设备入口 | 已登录 |
| `/diagnosis/:assetId` | 设备诊断、证据、安全和草稿创建 | 已登录 |
| `/work-orders` | 工单筛选、队列和审批状态 | 已登录 |
| `/work-orders/:workOrderId` | 工单快照、转换、审计和审批 | 已登录；审批动作限 `approver/admin` |

核心组件：

- `AppShell`：顶栏、侧栏、用户信息、全局连接状态；
- `AssetOverview`：只读设备卡片与知识包范围；
- `AssetPlate`：当前资产、型号、控制器和知识包上下文；
- `DiagnosisComposer`：问题输入、输入约束和提交状态；
- `DiagnosisResult`：事实、候选原因、检查步骤和升级条件；
- `EvidenceInspector`：引用、安全前置条件、不确定性和必需信息；
- `WorkOrderDraftDrawer`：草稿预填、确认和提交；
- `WorkOrderQueue`：工单筛选与状态列表；
- `ApprovalPanel`：引用快照、批准、拒绝及冲突恢复；
- `AsyncState`：统一加载、空状态和错误恢复界面。

本阶段不引入 Pinia。认证、当前设备和请求状态使用职责单一的 composable 管理；跨路由状态以 URL、服务端数据和最小会话状态为准。

## 5. 必需的后端契约补充

现有 `AssetResponse` 只有 `equipment_model_id`，不足以构造通用诊断请求。若由前端硬编码 `equipment_model_id -> pack_id/model/controller`，将直接破坏“切换设备不改代码”的验收目标。

因此设备响应增加只读字段：

```json
{
  "asset_id": "cnc-demo-001",
  "equipment_model_id": "haas-vf2-ngc",
  "pack_id": "cnc_pack_v1.0.0",
  "manufacturer": "Haas",
  "model_name": "VF-2",
  "controller_or_firmware_scope": "NGC",
  "display_name": "CNC 演示机 001",
  "status": "available",
  "synthetic": true,
  "version": 1
}
```

字段来自 `Asset.equipment_model` 关系，不能由前端推断。设备列表查询应预加载型号关系，避免序列化阶段的重复查询。该扩展不修改数据库表、知识包或诊断请求契约。

其余接口沿用现有 v0.3/v0.4 契约：

- `POST /api/auth/login`、`GET /api/auth/me`；
- `GET /api/equipment/assets`；
- `POST /api/diagnosis/query`；
- `POST /api/work-orders/drafts`；
- `GET /api/work-orders`、`GET /api/work-orders/{id}`；
- `POST /api/work-orders/{id}/approve`、`POST /api/work-orders/{id}/reject`。

## 6. 认证与浏览器连接

Bearer 令牌保存于当前标签页的 `sessionStorage`，并同步到现有 API 客户端的内存会话。页面加载时恢复令牌并调用 `/api/auth/me` 验证；登出、401、令牌过期或撤销时同时清除内存与 `sessionStorage`。

不在 URL、日志、错误提示或 DOM 文本中展示令牌。前端不提供伪造角色、手工粘贴令牌或免登录快速切换功能。演示角色切换通过正常退出和重新登录完成。

Vite 开发服务器将 `/api`、`/health` 和 `/ready` 同源代理到 `http://127.0.0.1:8100`。API 客户端默认使用同源相对地址，并保留 `VITE_INDUSTRIALOPS_API_BASE_URL` 覆盖能力。v0.5 不通过开放任意 CORS 来源解决浏览器连接问题。

## 7. 主数据流

```text
登录
→ /api/auth/me 验证角色
→ 获取设备列表与服务端型号上下文
→ 选择资产并进入 /diagnosis/:assetId
→ 用服务端 pack/model/controller 构造诊断请求
→ 展示结构化结果、引用、安全和不确定性
→ 满足条件时预填并提交工单草稿
→ 展示 pending_approval 与 thread_id
→ approver/admin 登录工单队列
→ 审阅服务端证据快照
→ 批准或填写理由拒绝
→ 刷新工单状态、决定与审计动作
```

切换资产时，必须在发起新请求前清空上一资产的诊断结果、引用、错误和草稿状态。页面不得在 CNC 资产下短暂显示真空泵结果，反之亦然。

## 8. 诊断与工单展示规则

### 8.1 诊断结果

前端按响应字段原义展示：

- `confirmed_facts`：已由证据确认的事实；
- `candidate_causes`：候选原因，禁止改写为确定根因；
- `inspection_steps`：允许展示的检查顺序；
- `safety_prerequisites`：安全前置条件；
- `uncertainties`：当前不确定性；
- `required_information`：继续判断所需信息；
- `escalation_conditions`：人工升级条件；
- `citations`：来源、修订版、页码与定位符。

`blocked`、`out_of_scope`、缺少必需信息或没有可执行步骤时，界面不显示“生成工单草稿”主操作，而是展示补充信息或人工升级路径。前端限制只改善用户体验，服务端仍是最终授权与安全边界。

### 8.2 工单草稿

草稿抽屉使用当前服务端诊断结果预填标题和描述，由用户选择有限的优先级并确认提交。请求只发送 `diagnosis_request_id`、`asset_id` 和允许编辑的草稿字段；诊断步骤、安全条件和引用继续由服务端快照生成，客户端不能覆盖。

创建成功后显示：

- `work_order_id`；
- `status=draft`；
- `approval_status=pending_approval`；
- `thread_id`；
- 已绑定引用数量。

### 8.3 审批

普通用户可查看工单，但不渲染可执行的批准和拒绝按钮。`approver/admin` 可批准；拒绝必须输入理由。审批按钮提交期间禁用，防止重复点击。

发生 `approval_already_decided` 或版本竞争时，不覆盖服务端结果，自动重新读取详情并展示已经生效的决定。

## 9. 状态与错误处理

每个异步区域使用统一状态：`idle`、`loading`、`success`、`empty`、`error`。加载超过短暂阈值时显示保留布局的骨架屏，避免内容跳动。

稳定错误码处理：

| 错误码 | 前端行为 |
|---|---|
| `unauthorized` | 清除会话，跳转登录页并说明登录已失效 |
| `forbidden` | 保留页面，只隐藏或禁用未授权动作并显示权限提示 |
| `asset_not_found` | 返回设备总览并提示资产不存在 |
| `work_order_draft_not_allowed` | 保留诊断结果，解释不能创建草稿并提供升级路径 |
| `approval_already_decided` | 重新加载详情，展示现有决定 |
| `stale_resource_version` | 重新加载资源，提示数据已更新 |
| 网络超时、断开或 5xx | 显示脱敏消息和重试按钮，不丢失已输入问题 |

Pydantic `422` 字段错误映射到对应表单字段。页面不得显示 SQL、堆栈、数据库 URL、checkpoint 内容、Bearer 令牌或原始内部异常。

## 10. TDD 与自动化验证

实现按以下红—绿—重构切片推进，每项生产行为必须先看到测试因目标能力缺失而失败：

1. 后端设备响应增加知识包和型号上下文；
2. API 客户端支持 JSON 请求、会话恢复、401 清理和结构化错误；
3. 登录、登出、路由守卫和角色展示；
4. 设备总览与两类设备切换；
5. 切换设备时清空旧诊断和引用；
6. 结构化诊断、引用、安全、不确定性和知识缺口渲染；
7. 工单草稿预填、允许条件和提交；
8. 工单队列、详情、批准、拒绝和竞争恢复；
9. 加载、空数据、网络失败、服务端失败和窄屏布局。

前端引入 Vitest、Vue Test Utils 和 jsdom，测试真实组件行为。保留 API 客户端纯逻辑测试，删除以源码字符串匹配代替用户行为的占位式断言。

自动化验收至少包括：

- 未认证用户无法进入受保护路由；
- 401 清除会话且不清除较新的替代会话；
- 设备响应包含服务端知识包与型号上下文；
- CNC 与真空泵诊断请求使用各自上下文；
- 切换设备后不保留旧结果、引用和草稿；
- 安全阻断和证据不足状态不展示可执行维修草稿动作；
- 引用显示修订版、页码和定位信息；
- 普通用户不能看到可执行审批控件；
- `approver/admin` 可批准或拒绝，拒绝理由必填；
- 重复审批或并发决定后界面以服务端最终状态为准；
- 所有新增组件具有加载、空状态和失败测试；
- 全量 Python 回归继续通过；
- 前端测试和 Vite 生产构建通过。

## 11. 真实演示验收

### 11.1 CNC 主案例

1. 登录普通用户；
2. 选择 `cnc-demo-001`；
3. 输入报警码和换刀症状；
4. 确认响应引用只属于 CNC 知识包；
5. 查看候选原因、检查顺序、安全前置条件和不确定性；
6. 创建工单草稿并记录 `work_order_id/thread_id`；
7. 退出并以 `approver/admin` 登录；
8. 审阅证据快照后批准或拒绝；
9. 确认最终状态、决定和审计动作可见。

### 11.2 真空泵迁移案例

1. 不修改代码、不重启应用；
2. 选择 `pump-demo-001`；
3. 输入真空度不足或异常噪声场景；
4. 确认设备铭牌、知识包、诊断内容和引用切换为真空泵范围；
5. 确认页面没有残留 CNC 报警、引用或草稿状态；
6. 完成诊断并验证安全和不确定性展示。

真实浏览器验收未完成前，README 和主规划不得将 v0.5 标记为 `release_verified`。

1. 四类核心视图及路由可用；

7. 错误、加载、空状态和窄屏布局有自动化覆盖；
