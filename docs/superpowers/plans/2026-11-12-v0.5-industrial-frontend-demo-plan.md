## 切片 1：设备上下文 API

1. 在 `tests/v04/test_assets_api.py` 描述资产读取响应必须包含来自设备型号的 `pack_id`、厂商、型号和控制器范围。
2. 运行目标测试，确认新字段缺失而失败。
3. 仅扩展 API 输出 schema 和查询加载策略；不改表结构、知识包或诊断请求。
4. 重跑目标测试及 v0.4 回归。

## 切片 2：前端测试与路由基础

1. 在 `frontend/package.json` 建立 Vitest、Vue Test Utils、jsdom 和 Vue Router 测试运行入口。
2. 先为公开登录路由和受保护路由守卫写失败组件/路由测试。
3. 实现应用入口、最小 `AppShell`、路由和会话 composable。
4. 验证无效/过期会话回到登录页，且不覆盖较新的会话。

## 切片 3：API 客户端与认证

1. 为 JSON 请求、token 持久化恢复、`/api/auth/me` 和结构化错误写失败测试。
2. 最小扩展 `api/client.js` 与认证 composable。
3. 实现登录表单、登出和中文可恢复错误提示。
4. 验证 token 不出现于路由、日志或错误 UI。

## 切片 4：设备总览与上下文切换

1. 为读取设备列表、按 `asset_id` 导航、CNC/泵上下文展示写失败测试。
2. 实现 `AssetOverview`、`AssetPlate` 和资产读取 composable。
3. 使用服务端 `pack_id/model_name/controller_or_firmware_scope` 构造后续诊断上下文；不得维护硬编码设备映射。
4. 验证资产不可用、加载、空状态和 404 恢复。

## 切片 5：诊断工作台与证据检查器

1. 为诊断请求构造、结构化结果、引用、安全、不确定性和知识缺口写失败组件测试。
2. 实现 `DiagnosisComposer`、`DiagnosisResult`、`EvidenceInspector` 和诊断 composable。
3. 安全阻断、域外或证据不足时隐藏工单草稿操作，明确显示补充信息/人工升级路径。
4. 验证切换设备时彻底清除上一设备的结果、引用、错误和草稿状态。

## 切片 6：工单草稿

1. 为只在允许结果中可打开草稿、预填字段、提交及 `pending_approval` 展示写失败测试。
2. 实现 `WorkOrderDraftDrawer` 与工单草稿请求。
3. 验证客户端不发送或篡改服务端快照字段；草稿拒绝时保留诊断结果。

## 切片 7：工单队列与审批

1. 为列表、详情、普通用户无审批操作、批准、拒绝必填原因及竞争恢复写失败测试。
2. 实现 `WorkOrderQueue`、详情和 `ApprovalPanel`。
3. 接收 `approval_already_decided` 或版本冲突后重新读取服务端最终状态。
4. 验证审批人和管理员的 UI 权限与后端一致。

## 切片 8：工业视觉、交付文档与端到端验证
