# v1.0 正式发布实施计划

**设计依据：** `docs/superpowers/specs/2026-11-22-v1.0-formal-release-design.md`  
**目标状态：** `v1.0_release_ready`（仅本地就绪，不推送、不打标签、不创建 GitHub Release）

## 不变约束

- 不修改诊断、检索、安全、审批、知识包或评测业务逻辑；
- 不修改阶段 0 冻结知识包和评测输入；
- 不把私有手册、模型、索引、数据库、凭据、本机报告或绝对路径放入 Git 或 ZIP；
- 演示录屏为用户明确跳过项，文档必须保留该事实；
- 所有发布工具行为遵循 RED-GREEN-REFACTOR；
- 由用户执行最终的 Git 推送、`v1.0.0` 标签和 GitHub Release。

## 阶段 1：冻结清单与校验器

1. 先编写失败测试，定义发布 manifest 的 schema、版本一致性、文件哈希、Alembic 单 head 和缺项 fail-closed 行为。
2. 新建轻量 `industrialops.release` 模块，加载 JSON manifest、计算 SHA-256、读取 tracked 文件和执行纯本地校验。
3. 将项目版本升级为 `1.0.0`，新增不含私有输入的 `config/release_manifest_v1.json`。
4. 运行定向测试并记录 RED/GREEN 结果。

## 阶段 2：安全发布包构建器

1. 先编写失败测试，定义“仅 Git 跟踪文件”、敏感路径与内容拒绝、稳定顶层目录、ZIP 可解压、SHA-256 输出和不合格构建清理。
2. 实现可注入 Git 文件来源的打包器，默认使用 `git ls-files`，将输出写入被忽略的 `dist/`。
3. 构建后再次扫描归档名称和文本内容；命中阻断项时移除本次 ZIP 和 SHA 文件，保留源文件。
4. 运行定向测试并记录 RED/GREEN 结果。

## 阶段 3：本地发布验证入口与公开材料

1. 先编写失败测试，定义发布验证入口在 manifest 校验、构建或验证证据缺失时返回非零，并生成脱敏构建报告。
2. 实现 `python -m industrialops.release.run`，依次执行 manifest 校验、发布包构建、归档校验和本地报告生成；不自动运行 Docker、Git 推送或外部服务。
3. 更新 README、架构、数据边界、评测摘要、已知限制、第三方声明、v1.0 发布说明、进度和任务状态；新增人工抽查清单与用户后续发布命令。
4. 运行定向测试并记录 RED/GREEN 结果。

## 阶段 4：最终验证与冻结

1. 运行 v1.0 发布工具定向测试和全仓 Python 回归。
2. 运行前端 `npm.cmd test` 与 `npm.cmd run build`。
3. 运行 `docker compose config`，不启动、停止或删除任何默认 Compose 资源。
4. 运行发布入口，生成本地 ZIP、SHA-256 和构建报告；检查 ZIP 可解压且内容无敏感项。
5. 按清单复核 CNC 告警、真空泵维护、跨包隔离、安全阻断、审批门禁的既有 v0.8 脱敏验收事实；本次不重新录屏，记录跳过项。
6. 所有强制项通过后更新本地状态为 `v1.0_release_ready`，提交代码和文档；不执行远端操作。

## 验收命令（实现完成后按实际可用解释器复核）

```powershell
python -m pytest tests/v10
python -m pytest

Push-Location frontend
npm.cmd test
npm.cmd run build
Pop-Location

docker compose config
python -m industrialops.release.run --project-root . --output-directory dist
```

如果任一命令因本机 Docker、模型或私有知识包前置条件不可用而无法完成，必须保留失败或跳过事实，不得复用旧结果写成当前通过。
