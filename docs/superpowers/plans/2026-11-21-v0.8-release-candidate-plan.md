# v0.8 Release Candidate 发布候选验收实施计划

**设计依据：** `docs/superpowers/specs/2026-11-21-v0.8-release-candidate-design.md`  
**状态：** 实施中  
**约束：** 不修改阶段 0 冻结包、评测集或指标口径；不新增产品功能；所有新增行为先观察失败测试。

## 阶段 1：可测试的 RC 验收核心

1. 建立 `industrialops.evaluation.v08` 包与 CLI 入口。
2. 用失败测试定义运行 ID、资源所有权标签、端口/项目名派生和既有资源拒绝规则。
3. 用失败测试定义追加式报告目录、原子 JSON 发布、拒绝覆盖和部分失败报告。
4. 用失败测试定义命令、环境、日志、错误和路径的统一脱敏。
5. 用失败测试定义延迟分位数、资源快照和并发样本统计。
6. 用失败测试定义故障矩阵判定：明确区分预期受控故障、意外失败、恢复成功和发布阻断。

**验证：** `tests/v08` 的最小定向回归先红后绿；不调用 Docker，不读取私有知识包或模型。

## 阶段 2：预检与声明真实性审计

1. 用测试定义 Docker/Compose、端口、必填配置、知识包、模型、输出目录和发布材料预检契约。
2. 接入既有冻结包校验和配置读取，但报告仅保存非敏感指纹与脱敏摘要。
3. 用测试定义 README/API/架构/许可证/数据边界声明到证据的映射检查；关键能力不能只靠关键词存在判定。
4. 增加 v0.8 运行手册的最小骨架与文档审计清单。

**验证：** 预检在小型临时夹具中可重现；缺少模型、包、端口冲突和缺少文档分别给出稳定原因码。

## 阶段 3：隔离 Compose 与冷启动观测

1. 为 RC 创建 Compose 覆盖配置和唯一项目名/端口/卷/网络映射。
2. 用测试验证不触碰默认 `industrialops` 资源、知识包和模型只读挂载、内部网络与离线变量。
3. 建立 Docker 命令适配器，记录无缓存构建、数据库健康、bootstrap、API 就绪和 Web 就绪时间。
4. 失败时保留本次资源及脱敏现场，清理仅支持精确运行 ID。

**验证：** 配置解析、命令生成和拒绝危险清理全自动验证；真实 Docker 执行留在阶段 6。

## 阶段 4：HTTP 主链路、离线诱饵与故障矩阵

1. 使用真实 HTTP 客户端实现健康/就绪、认证、双设备诊断、引用隔离、工单草稿、越权拒绝、审批和重启恢复步骤。
2. 为离线诱饵和内部回答故障服务建立受控测试夹具；不调用外部模型或上传私有资料。
3. 为模型缺失、知识包缺失、索引损坏、数据库异常、LLM 超时、LLM 错误和离线出站诱饵实现隔离场景与恢复检查。
4. 确保每个场景把状态、原因码、脱敏日志摘要和恢复结果追加到报告。

**验证：** 单元/集成夹具覆盖判定逻辑；真实容器故障注入在阶段 6 执行。

## 阶段 5：基线与浏览器执行层

1. 实现固定预热和样本次数的延迟采样、Docker 资源快照和小规模并发测量。
2. 将采样原始摘要、失败数、提供方/降级路径写入报告，禁止设置或暗含通过阈值。
3. 使用 Chrome/CDP 对已启动 RC Web 进行登录、设备切换、诊断、证据展示、工单和审批真实浏览器验收。
4. 记录脱敏浏览器步骤与截图引用，不记录密码、Token、厂商手册正文或完整证据文本。

**验证：** 统计逻辑自动化测试；浏览器执行器使用可注入客户端做契约测试。

## 阶段 6：完整 RC 验收、文档与发布证据

1. 执行全仓 Python 测试、前端测试/构建、Compose 配置检查和镜像内容边界检查。
2. 在真实 Docker 环境执行隔离无缓存冷启动、HTTP 主链路、故障矩阵、性能/资源/并发和浏览器验收。
3. 按 README 从零复现安装、启动、演示和评测命令，并更新 README、运行手册、API/架构、许可证/数据边界说明。
4. 保存不可覆盖的本地 RC 报告；报告所有强制项通过后才更新状态为 `release_verified`。
5. 记录未执行、失败和已知限制，且不将它们标记为通过。

## 验收命令顺序

每个切片遵守：写测试 → 运行并确认预期失败 → 最小实现 → 运行定向测试 → 重构 → 运行相关回归。每完成一阶段，更新 `task_plan.md`、`findings.md` 和 `progress.md`。

真实验收的推荐顺序：`preflight → cold_start → http_demo → fault_matrix → baseline → browser → truth_audit → finalize`。任一前置阶段失败时，停止依赖阶段并发布部分报告。
