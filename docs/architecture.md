# IndustrialOps Copilot 架构说明

## 定位与边界

IndustrialOps Copilot 是面向 Haas VF-2（NGC）和 Edwards nXDS 标准型号的本地工业运维演示平台。它使用两个冻结知识包、结构化关系表、检索元数据和证据约束诊断；不使用知识图谱、图数据库、图检索或真实设备控制。

厂商原始资料、派生语料、冻结包和本地模型均为 `local_evidence_only` 本地输入，不能进入 Git、镜像或公开发布包。设备、用户、工单和审计中的演示数据明确是合成数据。

## 部署拓扑

```text
浏览器
  │ 127.0.0.1:5174
  ▼
web (Vue/Nginx)
  │
  ▼
api (FastAPI / LangGraph)
  │                 ▲
  │                 │ bootstrap 成功后才启动 API
  ▼                 │
db (MySQL) ───► bootstrap（迁移、合成资产、包校验、索引构建）
```

Docker Compose 的服务顺序为 `db → bootstrap → api → web`。知识包和模型由宿主机只读挂载；数据库和可再生索引使用独立卷。`/health` 只表示 API 进程存活，`/ready` 会分别报告数据库、迁移、知识包、索引、本地模型和离线策略。

## 诊断链路

`POST /api/diagnosis/query` 经过 LangGraph 诊断工作流：解析意图和设备上下文、执行型号/控制器/版本兼容性过滤、检索同包的冻结证据、执行确定性安全门控和证据充分性判断，再组织结构化回答与页码引用。

默认 `INDUSTRIALOPS_OFFLINE=true`。此时回答器直接输出本地证据约束结果，不向外部模型发起请求。即使显式配置在线回答器，返回内容也必须通过字段、证据 ID 和引用校验；无法验证时回退到本地证据回答，不将候选原因表述为确定性根因。

## 工单与审批

诊断结果先在服务端保存证据快照；用户只能基于该快照创建工单草稿。草稿进入 LangGraph `interrupt()`，只有 `approver` 或 `admin` 才能批准或拒绝。checkpoint、审批决定和审计事件持久化在数据库中，因此 API 重启后可用相同 `thread_id` 恢复。工单不能绕过人工审批，也不会向真实设备发送控制指令。

## 发布与验收

v0.8 使用独立 Compose 项目名、端口和卷执行发布候选验收，避免接触既有 `industrialops` 资源。验收记录冷启动、主链路、离线行为、受控故障恢复、资源/延迟/并发观察值和浏览器操作结果；报告追加式生成并统一脱敏。只有真实无缓存部署、HTTP、浏览器、故障矩阵和文档真实性审计都通过，才能标记为 `release_verified`。

2026-11-22 的独立本机 RC 已满足上述条件并标记为 `release_verified`；逐项结果与边界见 [v0.8 本机发布验收](evaluation/v08-release-validation.md)。

## v1.0 发布冻结边界

v1.0 不改变上述运行架构。它从 Git 跟踪的公开文件构建本地 ZIP，并通过发布清单冻结产品版本、Alembic head、两个设备包身份、公开材料和评测摘要。原始厂商资料、冻结包、模型、索引、数据库卷、`.env`、本地原始报告与浏览器截图仍不得进入 ZIP。发布工具在打包前校验清单，在打包后重新扫描归档；任何真实连接串或受限路径都会导致构建失败。
