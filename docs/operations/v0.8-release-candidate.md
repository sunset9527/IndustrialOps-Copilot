# v0.8 Release Candidate 验收运行手册

## 目的与边界

v0.8 使用独立 Compose 项目名、端口、数据库卷和索引卷，模拟第一次获取项目的用户。它不会接触已有 `industrialops` Compose 项目，也不会修改阶段 0 冻结知识包、模型权重或评测集。

每次运行都必须使用新的、全小写的 `--run-id`（字母、数字与连字符）。验收事件和最终报告保存在本地 `data/evaluation/reports/v08/<run-id>/`，该目录包含私有环境信息指纹，不能提交 Git。

当前 CLI 已交付预检和无缓存冷启动两个阶段。HTTP 主链路、受控故障矩阵、基线和浏览器验收将在后续 v0.8 切片接入同一报告目录；在它们实际通过前，项目不得标记为 v0.8 `release_verified`。

## 前置条件

1. 在仓库根目录复制 `.env.example` 为 `.env`，设置本机数据库密码与三个私有路径。
2. `INDUSTRIALOPS_PACKS_PATH` 下必须有 `cnc_pack_v1.0.0` 与 `dry_vacuum_pump_pack_v1.0.0`。
3. BGE-M3 和 reranker 目录必须各含 `config.json`。
4. 使用与项目依赖兼容的 Python 环境；冷启动还需要可用的 Docker Desktop Linux 容器引擎。
5. 选择未占用的 RC 端口，例如 API `18100`、Web `15174`；不要使用已有演示栈正在使用的端口。

## 1. 仅执行安全预检

此步骤不调用 Docker、不连接数据库、不读取厂商手册正文或模型权重。它检查离线策略、冻结包目录、模型配置、端口和必需发布材料，并生成脱敏的最终报告。

```powershell
.\.venv-eval\Scripts\python.exe -m industrialops.evaluation.v08.run `
  --project-root . `
  --run-id v08-preflight-20261121-01 `
  --api-port 18100 `
  --frontend-port 15174 `
  --phase preflight
```

成功退出码为 `0`。失败退出码为 `1`；查看 `report.json` 中的稳定原因码，例如 `RC_PREFLIGHT_PACK_MISSING`、`RC_PREFLIGHT_BGE_MODEL_MISSING` 或 `RC_PREFLIGHT_PORT_UNAVAILABLE`。报告和事件已经脱敏，不要通过复制终端环境变量来排障。

## 2. 执行隔离无缓存冷启动

在预检通过后，以新的运行 ID 再执行冷启动。CLI 会执行严格限定为本次 `industrialops_rc_<run-id>` 项目的 `docker compose build --no-cache` 和 `docker compose up --detach`；构建失败时不会继续启动服务。知识包和模型仍是只读宿主机挂载。

```powershell
.\.venv-eval\Scripts\python.exe -m industrialops.evaluation.v08.run `
  --project-root . `
  --run-id v08-cold-20261121-01 `
  --api-port 18100 `
  --frontend-port 15174 `
  --phase cold-start
```

冷启动事件流位于 `events.jsonl`；最终摘要在 `report.json`。失败时保留该次 RC 容器、卷和脱敏日志证据，便于诊断。当前 CLI 不提供自动清理命令；不要用宽泛的 `docker compose down -v` 或删除名称不属于本次 `industrialops_rc_<run-id>` 的卷。

## 安全规则

- 默认必须保持 `INDUSTRIALOPS_OFFLINE=true`；不能为了“跑通”而改成在线模式。
- 不要把 `.env`、报告目录、知识包、模型、数据库卷、索引卷、备份或厂商资料提交到 Git。
- 不要删除 MySQL 卷来修复索引问题；可再生索引与数据库应独立处置。
- RC 端口、项目名和 run ID 是验收隔离边界的一部分，不能复用已有演示运行的资源。
