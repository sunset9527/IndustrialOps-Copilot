# v0.6 本地离线交付与恢复

## 冷启动

在 Windows PowerShell 5.1 中，从项目根目录复制 `.env.example` 为 `.env`，然后仅修改本机数据库密码和三条宿主机私有路径。`INDUSTRIALOPS_PACKS_PATH` 必须指向包含两个已冻结包的目录；两个模型路径必须分别包含本地 BGE-M3 与 reranker 的 `config.json`。这些私有资料不会被复制到镜像。

```powershell
docker compose config
docker compose up --build -d
docker compose logs bootstrap
docker compose ps
Invoke-RestMethod http://127.0.0.1:8100/health
Invoke-RestMethod http://127.0.0.1:8100/ready
```

当 `bootstrap` 显示完成、API 健康且 `/ready` 返回 `status=ready` 后，打开 `http://127.0.0.1:5174`。默认 `INDUSTRIALOPS_OFFLINE=true`：即使意外存在外部模型密钥，诊断也使用本地证据降级回答，不会调用外部模型服务。

## 状态与失败处理

`/health` 只代表 API 进程存活。`/ready` 还会报告数据库、迁移、两个冻结知识包、当前索引、两个本地模型和离线策略。收到 503 时按 `dependencies[].code` 处理：

- `DATABASE_*`：检查数据库容器与迁移；不要删除卷来“重试”。
- `PACK_*`：检查只读挂载是否指向原始冻结包及注册表版本。
- `MODEL_*`：检查两个本地目录和各自 `config.json`。
- `INDEX_*`：在知识包和模型身份正确时重建可再生产物。
- `CONFIG_*`：修复 `.env` 后重新运行 bootstrap。

索引损坏或身份过期时，只能删除明确名为 `industrialops_index-data` 的索引卷，再重新执行 bootstrap；不要删除 `mysql-data`。先用 `docker volume ls` 人工核对精确名称。

```powershell
docker compose down
docker compose up bootstrap
docker compose up -d api web
```

## 数据库备份与恢复

停止 API 与前端后备份 MySQL。备份文件包含合成资产、用户、会话、诊断记录、工单、审批、审计和 checkpoint；它不能替代知识包或模型的原始本地归档。

```powershell
docker compose stop api web
$backup = Join-Path $PWD ("industrialops-" + (Get-Date -Format 'yyyyMMdd-HHmmss') + ".sql")
docker compose exec -T db sh -c 'exec mysqldump -uindustrialops -p"$MYSQL_PASSWORD" industrialops' > $backup
```

恢复时先确认 `.env`、冻结包和模型版本，再启动数据库、导入备份、迁移、校验/重建索引，并最后启动 API 和前端。

```powershell
docker compose up -d db
Get-Content -Raw -LiteralPath $backup | docker compose exec -T db sh -c 'exec mysql -uindustrialops -p"$MYSQL_PASSWORD" industrialops'
docker compose run --rm bootstrap
docker compose up -d api web
Invoke-RestMethod http://127.0.0.1:8100/ready
```

以上命令不删除任何数据库卷。仅当已验证备份可用并明确决定放弃现有数据库时，才应由操作者单独执行卷删除。
